# dsh-mini-kit

给 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) 的两个小工具，一个包：

| 用途 | 入口 |
|---|---|
| 重启 DSH，并让当时**正在跑**的会话在重启后接着干 | `/restart` 斜杠指令 · `restart_dsh` 工具 |
| 看看现在有哪些会话在跑（工作区 + 会话名） | `list_running_sessions` 工具 |

`/restart` 是给人用的（输入 `/` 就出现在候选里），两个工具是给 Agent 用的——所以 Agent 干活干到一半也能自己重启，回来继续。

## 安装

在 DSH 桌面版里：**设置 → 插件 → 添加插件**，填 `dsh-mini-kit`；或者选「从本地目录」指向你克隆下来的这个仓库。

装完不用重启，新装的 bundle 会被 HMR 直接激活；插件列表里出现「迷你工具包」就成功了。

> 桌面版 profile 由应用自己管理，所以 `dsh plugin --profile desktop add …` 会被拒绝（那是给应用自带载体用的）。装插件请走界面。

## 用起来

### `/restart`

在输入框里敲 `/restart` 回车即可。它会：

1. 列出此刻正在跑轮次的会话；
2. 把这些轮次取消掉并等它们停稳（这样会话日志里留下的是干净的 `turn/end`，不是被砍断的半截轮次）；
3. 把这些会话记到 `~/.dsh/mini-kit/pending-restart.json`；
4. 把所有会话的缓冲事件强制刷盘；
5. 结束 DSH 进程树并重新拉起 `DeepSeek Harness.exe`；
6. 新进程启动后读那份记录，逐个给这些会话补一句「继续」，于是它们自己接着干。

**如果你是从一次工具调用里触发的**（Agent 自己按下去），那它当前这一轮不会被自己取消——插件会等这一轮自然结束后再动手（最多等 60 秒），否则等于在工具执行到一半时把执行者干掉。

### `list_running_sessions`

返回形如：

```
2 running session(s):
- MemoryMate / 修复登录页跳转
- Careful S / 整理发布脚本
```

没有会话在跑时返回一句话，不是空字符串。

### `restart_dsh`

和 `/restart` 完全同一套机制，区别只是调用者：它知道自己正在哪一轮里执行，因此会延后重启；`/restart` 是从输入框发起的，没有执行中的轮次，所以立即重启。

## 重启到底做了什么（以及代价）

桌面版的 Electron 外壳没有给 Host 插件任何「重启应用」的接口：外壳只认固定的一组 IPC 事件，preload 也没暴露 relaunch。所以这里的重启是**由插件拉起一个脱离进程树的助手**完成的：

- 先 `taskkill`（不带 `/F`，等于点关闭）请它退出，`gracefulExitMs` 内没走就强杀；
- 再显式杀掉 Host 自己的旧进程——它还占着 HTTP 端口，不清掉的话新实例会以「另一个 DSH 实例正在运行」启动失败；
- 顺手清扫同名的残留进程（渲染进程孤儿）；
- 最后用 `DeepSeek Harness.exe` 重新启动，并**去掉 `ELECTRON_RUN_AS_NODE`**（继承下来的话会把应用当 node 脚本启动，不会出窗口）。

诚实说明代价：这一步不是应用自己的退出流程，窗口会闪一下，约 3–5 秒回来；外壳自己的状态（窗口位置之类）是被硬切断的。会话数据不受影响，因为第 4 步已经强制刷盘了。

安全阀：如果父进程并不是 `DeepSeek Harness.exe`（比如你在终端里跑 `dsh web`），助手会**拒绝动手**并只写一行日志。

## 配置

| 字段 | 默认 | 说明 |
|---|---|---|
| `autoResume` | `true` | 重启后是否自动给记录里的会话补「继续」 |
| `resumePrompt` | 见下 | 补的那句话 |
| `resumeDelayMs` | `2500` | 新进程起来后等多久再开始恢复（等插件树装好） |
| `cancelTimeoutMs` | `20000` | 取消其它正在跑的轮次的总预算 |
| `quietWaitMs` | `60000` | 等「调用者自己那一轮」结束的上限，超时就直接重启 |
| `gracefulExitMs` | `3000` | 请应用退出后等多久再强杀 |
| `relaunchDelayMs` | `800` | 交接后到窗口消失之间的延迟（让结果先显示出来） |
| `stateDir` | 空 | 覆盖状态目录，空表示 `$DSH_HOME/mini-kit` |

`resumePrompt` 默认：

> DSH 刚刚重启，上一轮工作被中断了。请从中断的地方继续；如果其实已经完成，简要总结一下结果即可。

写在 profile 的 `cordis.patch.yml` 里即可，本包**故意不写** `config` 块，免得覆盖你的改动。

## 边界

- **只在桌面版可用**。`dsh web`／无头模式下没有可重启的应用进程，工具会返回一句说明，指令返回错误结果，都不会动手。
- 只列 / 只恢复**用户会话**。子代理派生的会话既不会出现在列表里，也不会被单独恢复——它们的工作属于发起它们的父会话。
- 「正在跑」= `Agent.status === 'running'`，也就是这一秒真的有轮次在推进；空闲会话不在列表里。
- 状态目录写不进去时**不会重启**：记不下要恢复谁，就不该把应用关掉。
- 记录文件读过即被认领（改名成 `.claimed`），所以一次恢复失败只丢一次补话，不会让每次开机都重来。

## 文件

```
~/.dsh/mini-kit/pending-restart.json          # 待恢复清单（读过即认领）
~/.dsh/mini-kit/pending-restart.json.claimed  # 已认领
~/.dsh/mini-kit/restart.log                   # 助手进程的日志：谁被杀、有没有拒绝、有没有重拉成功
```

重启没生效时先看 `restart.log`。

## 开发

```sh
npm test
```

测试不需要 DSH，也不需要真的重启：`restart_dsh` 的计划、取消、清单写入、恢复流程都在假 context 上跑，唯一被替换掉的是「拉起助手进程」和「当前是不是桌面版」这两个接缝。
